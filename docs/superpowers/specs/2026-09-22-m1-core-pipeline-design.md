# M1: Core Telemetry Pipeline - Design

## Goal

A working AWS data pipeline for synthetic medical device telemetry: devices upload
procedure logs, the platform validates and stores them, and a REST API serves them.
All infrastructure is defined with AWS CDK (Python).

## Roadmap context

| Milestone | Scope |
|---|---|
| **M1 (this spec)** | Simulator, S3, SQS, Lambda, RDS, FastAPI on ECS Fargate behind an ALB, CDK, GitHub Actions CI |
| M2 | Same API image on an optional EKS stack and on a local Kubernetes cluster (shared manifests) |
| M3 | Jenkins on the local Kubernetes cluster for automated deploys |
| M4 | CloudWatch dashboards and alarms, runbook, incident drill with root-cause analysis |

M2-M4 each get their own spec.

## Architecture

### Data flow

1. `simulator` CLI generates synthetic procedure logs as JSON Lines and uploads them to
   `s3://<raw-bucket>/raw/device=<id>/date=<yyyy-mm-dd>/<procedure_id>.jsonl`.
2. S3 event notification (filtered to the `raw/` prefix) sends a message to an SQS queue (with a dead-letter queue, max 3 receives).
3. Ingest Lambda (container image, SQS event source) reads the object, validates each line with Pydantic,
   and writes it to RDS Postgres in one transaction.
4. FastAPI container on ECS Fargate, behind an ALB, serves read-only REST endpoints.

### Network

- VPC across 2 AZs, public and private subnets.
- ALB in public subnets. Fargate, Lambda, and RDS in private subnets.
- One NAT Gateway for private subnet egress. (Replacing it with a NAT instance is a
  candidate cost optimization for later.)
- Security groups: ALB accepts only the operator's IP (passed at deploy time via CDK
  context, never committed); Fargate accepts only the ALB; RDS accepts only Fargate and Lambda.

### CDK stacks

| Stack | Resources | Destroy behavior |
|---|---|---|
| `NetworkStack` | VPC, subnets, NAT Gateway | Destroyed |
| `DataStack` | S3 raw bucket, SQS queue + DLQ, RDS Postgres (`db.t4g.micro`), DB credentials in Secrets Manager | Destroyed (bucket objects auto-deleted, no RDS snapshot) |
| `IngestStack` | Ingest Lambda (container image, ARM64), SQS event source mapping | Destroyed |
| `ApiStack` | Docker image asset (ECR), ECS cluster, Fargate service (ARM64), ALB | Destroyed |

Estimated always-on cost: ~$70/month (NAT ~$32, ALB ~$16, RDS ~$13, Fargate ~$9).
Default operating mode is `cdk destroy --all` between sessions. All data is synthetic and
regenerated by the simulator after a redeploy. Snapshot-based restore is a possible later improvement.
The one-time CDK bootstrap stack (asset bucket and ECR repo) stays between sessions; its cost is negligible.

## Data model

| Table | Columns |
|---|---|
| `devices` | `id` text PK, `model` text, `first_seen` timestamptz, `last_seen` timestamptz |
| `procedures` | `id` uuid PK, `device_id` text FK, `procedure_type` text, `started_at` timestamptz, `ended_at` timestamptz, `status` text |
| `events` | `id` bigserial PK, `procedure_id` uuid FK, `ts` timestamptz, `event_type` text, `payload` jsonb; index on `(procedure_id, id)` for cursor pagination |
| `ingest_files` | `s3_key` text PK, `status` text (`processed` or `quarantined`), `event_count` int, `error` text, `received_at` timestamptz, `processed_at` timestamptz |

- Database access: `psycopg` 3 (with `psycopg-pool` in the API), no ORM.
- Migrations: numbered SQL files in `services/api/src/api/migrations/`, applied by
  `python -m api.migrate` when the API container starts. A Postgres advisory lock makes
  concurrent starts safe.
- Idempotency: each file is processed in one transaction; `ingest_files.s3_key` is unique,
  so a redelivered SQS message is a no-op.

## Log file format

One JSON object per line. The first line is a procedure header; the rest are events.

```json
{"kind": "procedure", "procedure_id": "<uuid>", "device_id": "dev-001", "model": "sim-x1", "procedure_type": "endoscopy", "started_at": "2026-09-22T14:00:00Z", "ended_at": "2026-09-22T15:10:00Z", "status": "completed"}
{"kind": "event", "ts": "2026-09-22T14:02:13Z", "event_type": "instrument_attached", "payload": {"instrument": "grasper"}}
```

Pydantic models for both line types live in `packages/telemetry` and are shared by the
simulator and the ingest Lambda.

## REST API

FastAPI, read-only, OpenAPI docs at `/docs`.

| Endpoint | Purpose |
|---|---|
| `GET /health` | ALB health check; 503 if the database is unreachable |
| `GET /devices` | List devices |
| `GET /devices/{device_id}/procedures` | Procedures for a device |
| `GET /procedures/{id}` | One procedure |
| `GET /procedures/{id}/events?event_type=&limit=&cursor=` | Events, cursor-paginated by `id` |
| `GET /ingest/files?status=` | Ingest results, e.g. quarantined files and their errors |

No user authentication in M1 (synthetic data, ALB restricted to operator IP).

## Error handling

- **Invalid file** (validation fails, or duplicate `procedure_id`): copy the object to `quarantine/`, record
  `ingest_files` with `status=quarantined` and the error, and treat the message as
  handled (no retry).
- **Transient error** (e.g. database unavailable): report the item as a batch item
  failure; SQS retries; after 3 receives the message goes to the DLQ.
- **API**: 404 for unknown IDs, 422 for invalid parameters.

## Testing

| Layer | Approach |
|---|---|
| Schema | Unit tests on Pydantic models (valid and invalid lines) |
| Ingest | Handler tests against real Postgres (testcontainers) and moto for S3: happy path, quarantine, idempotent redelivery, partial batch failure |
| API | FastAPI `TestClient` against the same Postgres container |
| Infra | CDK assertion tests: RDS not public, bucket blocks public access, queue has DLQ, Fargate ingress only from ALB |
| End to end | `smoke_test.py` uploads one valid and one invalid file, polls the API until both results appear |

## CI

GitHub Actions on push and pull request: `ruff check`, `ruff format --check`, `pytest`,
`cdk synth`. No AWS credentials in CI during M1. Deploys run from the operator's machine
with `cdk deploy`. Automated deploys arrive in M3.

## Repository hygiene

The repository is public.

- No AWS account IDs, access keys, IP addresses, or kubeconfig content in committed files.
- `cdk.context.json` is git-ignored.
- Operator IP and any account-specific values come from environment variables or CDK
  context at deploy time.

## Versions

Verify current versions at implementation time rather than assuming: AWS CDK v2,
Lambda Python runtime, RDS PostgreSQL engine, FastAPI, psycopg.

## Done when

1. `cdk deploy --all` succeeds in a clean account.
2. A simulated upload appears via the API within about one minute.
3. An invalid upload appears as quarantined via `GET /ingest/files?status=quarantined`.
4. `cdk destroy --all` removes every stack resource (no orphaned buckets, snapshots, or log groups left billing).
5. CI passes on `main`.
